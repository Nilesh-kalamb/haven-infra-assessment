# B0 — The `count` trap

## What happens when a middle landlord account is removed?

When Terraform uses `count` with a list of landlord accounts, it identifies resources using numeric indexes such as:

- `aws_s3_bucket.landlord_media[0]`
- `aws_s3_bucket.landlord_media[1]`
- `aws_s3_bucket.landlord_media[2]`

Suppose the original list contains three landlord accounts: A, B, and C.

Initially, Terraform creates three S3 buckets:

- Index `[0]` represents landlord account A.
- Index `[1]` represents landlord account B.
- Index `[2]` represents landlord account C.

Now suppose landlord account B is removed from the middle of the list.

The updated list becomes A and C.

Terraform now sees:

- Index `[0]` still represents account A.
- Index `[1]` now represents account C.

Terraform compares resources by their indexes rather than by their actual landlord account IDs.

As a result, Terraform sees that the resource at index `[1]` now represents account C instead of account B. It may plan to destroy and recreate resources because their index-based identities have shifted.

The existing bucket for account C at index `[2]` may be destroyed, and a new bucket may be created at index `[1]`.

## Why is this dangerous?

Each landlord account has its own S3 bucket containing property-related media.

Using `count` can associate an existing bucket with the wrong landlord account after a list modification.

This can result in:

- Unnecessary resource destruction or replacement.
- Risk of losing access to existing landlord media.
- Accidental reassignment of infrastructure.
- Unexpected downtime and operational issues.
- Potential data loss if bucket deletion is performed.

This is particularly dangerous because S3 buckets may contain important property photos and business data.

## What is the fix?

Replace `count` with `for_each` and use the stable, unique `landlord_account_id` as the resource key.

Example:

```hcl
resource "aws_s3_bucket" "landlord_media" {
  for_each = {
    for account in var.landlord_accounts :
    account.landlord_account_id => account
  }

  bucket = "haven-media-${each.key}"
}
```

With `for_each`, Terraform identifies each bucket using its landlord account ID instead of its list position.

For example:

- `aws_s3_bucket.landlord_media["A"]`
- `aws_s3_bucket.landlord_media["B"]`
- `aws_s3_bucket.landlord_media["C"]`

If account B is removed, Terraform targets only B's bucket. The buckets belonging to A and C retain their stable identities.

## Conclusion

Using `for_each` with `landlord_account_id` prevents index shifting and reduces the risk of unintended infrastructure changes when landlord accounts are added or removed. It provides stable resource identity and makes infrastructure management safer and more predictable.
